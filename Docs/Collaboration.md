# Codex·Claude 교대 작업

공유 저장소: https://github.com/sungbin25/steel-district.git

## 작업 시작

1. `git status -sb`, 현재 브랜치와 최근 커밋을 확인한다. 로컬 변경이 있으면 diff를 읽고 이전 작업자의 변경을 보존한다.
2. 원격을 확인할 때 `git fetch origin` 후 현재 브랜치와 추적 브랜치의 차이를 읽는다. fetch만으로 작업 파일이 갱신되지는 않는다. 깨끗한 작업 트리에서 최신화할 때는 fast-forward를 우선하고, 이력이 갈라졌다면 차이를 검토한다. 강제 덮어쓰기·자동 stash·무조건적인 충돌 해결을 하지 않는다.
3. AGENTS.md → CurrentState.md → 해당 모듈 문서 순으로 필요한 범위만 읽는다. 이전 대화가 다른 도구에 전달되었다고 가정하지 않는다.
4. 같은 작업 디렉터리는 한 도구만 수정한다. 교대 시 이전 도구의 편집과 Unity 저장이 끝났는지 확인한다. 씬 파일과 열린 Editor의 미저장 상태는 별개다.

## 작업 종료와 업로드

- CurrentState에는 완료한 기능·남은 문제·실제 확인한 범위·다음 작업을 기록하고, 구조 변경은 ProjectMap과 모듈 문서에 반영한다.
- 커밋 전 diff를 확인하고 해당 작업의 코드·에셋·`.meta`·문서를 함께 포함한다. 다른 작업의 변경을 일괄 커밋하지 않는다.
- 업로드 작업에서는 로컬 커밋과 push 성공을 구분하여 보고한다. push가 거절되면 원격 변경을 확인하고 force push로 우회하지 않는다.
- 인계 시 브랜치·커밋·업로드 여부·미커밋 파일을 알려 다음 작업자가 정확한 기준에서 시작하게 한다.
- Library·Temp·Logs 등은 .gitignore로 제외된다. 공유에 필요한 검증 결과와 실패 원인은 Docs에 요약한다. 로컬 로그 링크만으로 인계를 끝내지 않는다.

## 검증 정책

사용자 요청으로 주행시험은 중단된 상태다. 일반적인 기능 수정 요청은 주행시험 재개 허가가 아니다. 컴파일·정적 확인·컴포넌트 참조 확인만 필요한 범위에서 수행하고, 실제 실행하지 않은 검사를 통과했다고 보고하지 않는다.
