# 메인 화면과 월드 진입 시나리오

2026-09-16 사용자 시나리오를 기록한 구현 기준이다. 2026-09-23 보유 차량/상점 목록·3D 미리보기·성능 표시·월드 왕복을 구현했다. 실제 사용법과 제한은 [VehicleSelection](VehicleSelection.md)을 따른다. 아래 업그레이드·개조·구매·임무·이벤트는 후속 설계이며 구현 완료와 구분한다.

## 확정된 사용자 흐름

1. 게임을 실행하면 사용자에게 메인 화면 씬을 표시한다.
2. 화면 상단의 상점·차고·임무·이벤트 버튼으로 해당 내용을 선택하고 확인한다. 포르자 호라이즌은 화면 구성과 탐색 흐름의 참고 방향이다.
3. 상점이나 차고에서 자동차 썸네일을 누르면 해당 차량의 3D 모델을 불러와 둘러볼 수 있다.
4. 이 화면에서 차량을 업그레이드하고 개조할 수 있다.
5. 월드 진입 버튼을 누르면 월드로 이동한다.

## 화면 구성 제안

메인 씬을 공통 화면으로 두고 상단 메뉴 선택에 따라 UI 패널을 전환한다. 차고와 상점은 차량 목록과 3D 미리보기를 공유하고, 임무·이벤트는 각자의 목록과 상세 정보를 표시한다. 상단 탭을 누를 때마다 전체 씬을 다시 로드하지 않는다.

| 화면 영역 | 역할 |
|---|---|
| 상단 메뉴 | 상점·차고·임무·이벤트 선택, 현재 메뉴 표시 |
| 차량 목록 | 차종 이름·썸네일·소유 여부·선택 표시 |
| 중앙 미리보기 | 선택한 차량 한 대를 표시하고 회전·확대/축소 |
| 차량 상세 | 차량 정보, 업그레이드·개조 진입, 변경 전후 비교 |
| 월드 진입 | 출전 차량 표시, 준비 상태에 따라 활성화 |

PC는 드래그와 휠, 모바일은 한 손가락 드래그와 핀치로 둘러보는 방식을 제안한다. UI를 누르거나 스크롤하는 입력은 미리보기 카메라에 전달하지 않는다. 최종 배치·아트·입력 감도는 후속 화면 작업에서 정한다.

## 차량 선택·개조 상태

썸네일로 보고 있는 차량과 실제 월드에 출전할 차량을 별도 상태로 관리한다. 상점에서 미소유 차량을 구경하는 것만으로 소유 차량이나 출전 차량이 바뀌지 않게 한다. 차고에서 소유 차량을 출전 차량으로 선택하는 조작을 제공한다.

개조 중에는 임시 편집 상태로 모델과 성능 변화를 미리 보여준다. 적용 시 유효성을 확인하고 확정된 구성을 기록하며, 취소 시 이전 구성으로 돌아간다. 변경을 적용하지 않은 상태에서 차량·메뉴를 이동하거나 월드 진입을 누르면 적용/버리기/계속 편집 중 하나로 처리한다. 적용에 실패하면 이전 확정 상태를 유지하고 실패 원인을 표시한다.

미소유 차량의 개조는 미리보기까지 허용하는 것을 기본 제안으로 둔다. 구매와 비용 차감, 소유권 부여는 별도 거래 규칙과 판정 주체를 정한 뒤 연결한다. 임시 로컬 값만으로 크로스플레이의 재화·소유권이 확정되었다고 처리하지 않는다.

## 씬과 모듈 책임 제안

| 모듈 | 책임 |
|---|---|
| 메인 화면 | 탭 전환·목록·상세·버튼 상태. 차량 물리와 거래 판정을 직접 수행하지 않음 |
| 차량 카탈로그 | 안정적인 차종 ID, 썸네일, 미리보기 모델과 주행 프리팹 연결 |
| 소유 차량 데이터 | 차량 개체 ID, 차종 ID, 확정된 장착·업그레이드·외형 구성 |
| 미리보기 | 모델 로드/해제, 카메라, 편집 결과 표시. 주행 입력·물리·타이어 효과를 실행하지 않음 |
| 개조 | 편집 초안·호환성·변경 비교·적용/취소. UI와 분리 |
| 씬 전환 | 중복 진입 차단, 준비 상태 확인, 월드 로드, 차량 생성, 실패 복귀 |
| 저장·진행 | 기기 설정과 공유 진행을 구분하고 확정된 데이터의 기록·복구 담당 |

메인 씬은 `Assets/Scene/MainMenuScene.unity`, 월드는 기존 `Assets/Scene/GameScene.unity`다. 월드 컨트롤러가 배치 차량과 생성 차량의 활성화를 관리하고 추적 카메라를 연결한다. 차량 튜닝과 기존 스크립트 GUID는 보존한다.

현재 빌드 첫 씬은 MainMenuScene이고 GameScene이 이어진다. 기존 OutdoorsScene 등록은 보존했으며 이번 진입 흐름에서는 사용하지 않는다. 별도 초기화 씬은 아직 없으며 도입하더라도 사용자에게 처음 보이는 화면은 메인 화면으로 유지한다.

## 월드 진입과 복귀

`메인 화면 → 출전 차량·확정 개조 확인 → 전환 중 → 월드 로드 → 차량 생성·입력/카메라 연결 → 주행 가능`

- 전환 요청 시 확정된 차량 ID와 개조 구성을 하나의 스냅샷으로 고정한다. 미리보기 GameObject나 Rigidbody를 씬 사이에 옮기지 않는다.
- 전환 중에는 재입력과 구성 변경을 막고 로딩 상태를 표시한다. 빠른 연속 클릭으로 월드나 차량이 여러 개 생성되지 않게 한다.
- 모델·필수 구성·월드 준비가 실패하면 메인 화면으로 복구하고 선택 상태와 확정 구성을 유지한다. 재시도는 가능한 상태에서만 제공한다.
- 씬별 카메라·AudioListener·EventSystem·입력 소유권을 정리한다. 월드 준비 후 미리보기 모델과 전용 리소스를 해제한다.
- 월드에서 메인으로 돌아오는 경로도 전환 검증에 포함한다. 복귀 시 HP·탄약 회복이나 중복 보상이 자동 발생하지 않게 한다. 실제 복귀 UI와 게임 규칙은 후속 결정 항목이다.
- 온라인 월드의 접속·매칭·권한 검증은 별도 설계 대상이다. 로컬 씬 로드 성공을 온라인 접속 성공으로 취급하지 않는다.

## 저사양 기기 기준

목표는 [플랫폼 기준](PlatformAndPerformance.md)의 PC·Android 우선, 저사양 60 FPS다. 미리보기 모델은 동시에 한 대만 유지하고 썸네일은 개별 3D 렌더 대신 이미지 목록으로 제공한다. 모델 로드는 비동기로 처리하며 빠른 선택 변경 시 마지막 선택만 화면에 반영하고 이전 요청의 리소스를 정리한다.

미리보기와 실제 주행은 같은 차종·개조 정의를 사용하되 표시용 구성과 물리 구성은 분리한다. 미리보기 카메라는 전용 환경만 렌더링하도록 구성한다. 품질·해상도·조명 비용은 실기기 측정으로 정한다. 현재 HDRP의 모바일 제약과 URP 전환 검토는 여전히 남아 있다.

## 순차 구현과 완료 조건

| 순서 | 구현 범위 | 완료 조건 |
|---|---|---|
| 1 | 메인 화면 씬·상단 탭·공통 UI | 게임 시작 시 메인 화면 표시, 메뉴 이동, PC/모바일 화면 비율 확인. 미구현 메뉴 내용은 준비 중으로 명확히 표시 |
| 2 | 차량 카탈로그·썸네일·3D 미리보기 | 기존 모델을 재사용해 차량 전환·회전·확대/축소, 빠른 연속 선택과 로드 실패 처리 |
| 3 | 출전 차량 선택·월드 전환 | 선택한 소유 차량으로 GameScene 진입·복귀, 중복 차량/카메라 없음, 실패 시 복구 |
| 4 | 업그레이드·개조·기록 연결 | 초안과 확정 구성 분리, 적용/취소, 미리보기와 실제 주행 결과 일치, 재시작 복원 |
| 5 | 상점 거래·임무·이벤트의 실제 기능 | 별도로 확정한 콘텐츠·재화·온라인 권한 규칙과 연결 |

1~3단계를 먼저 연결하면 기존 차량 에셋으로 게임 진입 흐름을 검증할 수 있다. 4단계 전에는 변경 가능한 업그레이드/개조 항목을 정해야 하며, 5단계 전에는 구매·재화·임무·이벤트·접속 정책을 정해야 한다. 문서에 제시되지 않은 가격·보상·기본 소유 차량을 임의의 확정 사양으로 만들지 않는다.
